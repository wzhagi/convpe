\begin{abstract}
	ConvPE (Convolutional Position Embedding) substantially improves both the parameter efficiency and training performance of Transformers. At the cost of only 3.2\% additional parameters and roughly proportional computation, it achieves a 14.6\% reduction in training loss, decreasing from 2.60 to 2.22. ConvPE uses convolution to generate attention score biases, making it compatible with various Transformer architectures and high-dimensional modalities. The code for ConvPE is publicly available at \url{https://github.com/wzhagi/convpe}.
\end{abstract}
\keywords{Position Embedding \and Language Models \and Transformers \and Attention \and Vision Transformers}

Transformers~\cite{vaswani2017attention} are insensitive to input order. However, word order is crucial for language understanding. Explicit or implicit position embeddings are therefore necessary to inject order information into the model~\cite{devlin2019bert,radford2019language,su2021roformer}.

This paper proposes ConvPE, a novel and efficient position embedding scheme. ConvPE embeds position information into attention score biases, trading a minor parameter overhead for significant performance gains, as shown in Figure \ref{fig:fig1}. Its design allows the model to switch freely between different attention masks and is compatible with various Transformer architectures. It also naturally supports high-dimensional modalities with n-dimensional convolution.

The main contributions of this paper are as follows:

1. We propose the ConvPE architecture that combines high performance and broad compatibility.

2. We study the influence of ConvPE hyperparameters and architecture.

3. We verify the effectiveness of ConvPE in language model pretraining.

4. We verify the effectiveness of ConvPE2D in visual model training.

5. We developed high performance TileLang\cite{DBLP:journals/corr/abs-2504-17577} kernels for ConvPE.


\section{Background}

\subsection{Attention Mechanism}


Given the input query $
Q \in \mathbb{R}^{S_q \times D_k}$ , key $K \in \mathbb{R}^{S_{kv} \times D_k}$, and value $V \in \mathbb{R}^{S_{kv} \times D_v}$, the computation of scaled dot-product attention~\cite{vaswani2017attention} $O\in \mathbb{R}^{T \times D_v}$ is:

$$
O = \mathrm{Attention}(Q,K,V) = \mathrm{softmax}\left(\frac{QK^\top}{\sqrt{d_k}} + \mathbf{B}\right)V
$$

$T$ is the query sequence length. $S$ is the key/value sequence length. $\mathbf{B}\in\mathbb{R}^{S_q\times S_{kv}}$ is the attention score bias. Causal models introduce a causal mask $M\in\mathbb{R}^{S_q\times S_{kv}}$ that sets the attention score bias $\mathbf{B}$ for invisible positions to $-\infty$. With batch size and multi-head settings, $Q,K,V,O$ additionally have $B,H$ dimensions.

\subsection{Position Embedding}
Existing position embedding schemes can be roughly divided into five categories:

1. \textbf{Absolute Position Embedding}\cite{vaswani2017attention}: adds a fixed positional bias, usually sine waves, to the input vector. It is simple to implement, but its performance is usually limited.

2. \textbf{Learnable Positional Bias}\cite{devlin2019bert,radford2019language}: adds a learnable positional bias to the input sequence. It is typically adopted in limited-window settings, such as spatial dimensions in vision models or fixed-rate compression.

3. \textbf{Rotary Position Embedding}\cite{su2021roformer}: encodes position as a rotation matrix and applies it to queries and keys, so that attention scores depend on relative positions. RoPE has been widely adopted in modern large language models, enabling long-context extension via frequency scaling, such as YaRN\cite{peng2024yarn}.

4. \textbf{Attention Score Bias}: adds a positional bias $B$ to attention scores\cite{raffel2020exploring}\cite{press2021train}\cite{chang2021convolutionsselfattentionreinterpretingrelative}. RoPE can be viewed as a rotation-based equivalent, as it also makes attention scores depend on relative positions.

5. \textbf{No Position Embedding (NoPE)}\cite{kazemnejad2023impact}: adds no explicit position embeddings; instead, it relies on model structure and causal attention masks to implicitly learn positional information requiring no explicit Position Embedding\cite{kimi2026k3}.


\section{Method}

ConvPE use a convolution to generates windowed attention score bias $\mathbf{B}_{ConvPE}\in\mathbb{R}^{B\times S\times H_b\times  W}$ for self-attention tokens $X\in\mathbb{R}^{B\times S\times D}$ within the convolution window.

\begin{figure}[!ht]
    \centering
    \begin{minipage}{0.52\textwidth}
        \centering
        \includegraphics[width=\linewidth]{FIGURES/convpe.jpeg}
    \end{minipage}
    \hfill
    \begin{minipage}{0.38\textwidth}
        \centering
        \includegraphics[width=\linewidth]{FIGURES/score_bias.jpeg}
    \end{minipage}
\end{figure}

\begin{equation*}
\mathbf{B}^{b,h,s_q,s_{kv}}=
\begin{cases}
\mathbf{B}_{\mathrm{ConvPE}}^{b,s_q,h\%H_b,w}, & w\in [0,W-1] \text{ where } w=s_{kv}-s_q+W-1\\
0, & \text{otherwise}.
\end{cases}
\end{equation*}


The hyperparameters are:
\begin{itemize}
\item $W$: convolution window size.
\item $C$: out features of linear projection and in channels of convolution.
\item $H_{b}$: number of score bias heads.
\end{itemize}

The convolution takes $C$ input channels, uses a kernel of size $W$, and outputs
$H_b\times W$ channels. The projection has $D\times C$ parameters and
the convolution has $W^2\times C\times H_b$ parameters; the computation (MACs) per token is the same as the parameter count.

To reduce the convolution parameter count, we introduce three additional
hyperparameters:
\begin{itemize}
\item $\mathrm{Groups}$: number of convolution groups;
\item $\mathrm{Share}$: whether to share weights across convolution groups;
\item $\mathrm{Rank}$: rank used in the low-rank convolution.
\end{itemize}


\section{Experiments}
All models in our experiments use Multi-Query Attention (MQA)\cite{shazeer2019fast}, with $K=V$\cite{deepseek2026v4}. Each attention layer has $D_{model} \times D_{head} \times (2\times N_{heads}+1)$ parameters. Each feed-forward layer uses SwiGLU\cite{shazeer2020glu} and has $8\times D_{model}^2$ parameters. 

\subsection{Hyperparameter Search}
We train each model for one epoch on WikiText-103~\cite{merity2016pointer} and record the validation loss. Training uses the Hugging Face Trainer~\cite{wolf2020transformers}, AdamW~\cite{loshchilov2019decoupled}, and the GPT-2 tokenizer~\cite{radford2019language}. The training hyperparameters are: batch size $4$, sequence length $1024$, learning rate $3\times10^{-4}$ with cosine learning-rate scheduler, and seed $42$.

We train two types of backbone models, a tiny backbone with $N_{layers}=12$, $D_{model}=192$, $N_{heads}=3$, $D_{head}=64$, and a base backbone with $N_{layers}=12$, $D_{model}=768$, $N_{heads}=12$, $D_{head}=128$. The model name format is "\texttt{backbone RoPE/NoPE  $W$ $C$ $\mathrm{Rank}$ $H_{b}$ $\mathrm{Groups}$ $\mathrm{Share}$}". For example, "\texttt{tiny rope w128d6r128h3g1s}" denotes a tiny backbone using RoPE with $W=128$, $C=6$, $\mathrm{Rank}=128$, $H_b=3$, $\mathrm{Groups}=1$, and $\mathrm{Share}$ weights. For simplicity, model names may omit the default configuration: \texttt{NoPE}, \texttt{r0}(no low-rank convolution), \texttt{h1} ($H_b=1$), \texttt{g1}($\mathrm{Groups}=1$), and \texttt{s0} (no weight sharing).

First, we train tiny models with hyperparameters around "\texttt{nope w128d6r0h3g1}". Figure \ref{fig:wt103t} shows that all ConvPE variants outperform the RoPE baseline. The largest gains come from increasing the window size and the projection dimension. Using grouped convolution causes the largest performance drop. RoPE integration and other parameter-saving methods show minor differences from "\texttt{nope w128d6r0h3g1}".

We then train base model with hyperparameters around "\texttt{nope w128d4r0h4g1}" and "\texttt{nope w128d16r0h1g1}". Figure \ref{fig:wt103b} shows that $H_b=1$ without any parameter-saving technique achieves the best balance between performance and parameter efficiency.

In additional experiments, we also try using $X$ , $Q$\cite{chang2021convolutionsselfattentionreinterpretingrelative} and $KV$ as the convolution input, but performance drops.

\subsection{Pretraining}

We choose "\texttt{base w128d16}" as the ConvPE variant configuration for performance and throughput considerations. We train the RoPE baseline \texttt{base RoPE} and the ConvPE variant from scratch on the first 3B tokens of FineWeb-Edu-10BT. We use Muon\cite{jordan2024muon} to optimize the 2D parameters, excluding the embedding layer and the language head, with a learning rate of $3\times10^{-3}$, while Adam\cite{DBLP:journals/corr/KingmaB14} optimizes the remaining parameters at a learning rate of $3\times10^{-4}$, both using a cosine learning-rate scheduler. The training hyperparameters are: batch size $4$, gradient accumulation steps $4$, sequence length $1024$, and seed $42$.

\begin{figure}[!ht]
    \centering
        \centering
        \includegraphics[width=\linewidth]{FIGURES/pretrain.png}
        \caption{Pretraining curve on first 3B tokens of FineWeb-Edu-10BT}
        \label{fig:pretrain}
\end{figure}

Figure\ref{fig:pretrain} shows that ConvPE converge farster and better than the RoPE baseline. We implement high-performance Flash MQA kernels in TileLang and benchmark two model configurations: \texttt{base RoPE} with $124.84$M parameters and \texttt{base w128d16} with $128.13$M parameters ($+2.64\%$), using a batch size of $4$ and a sequence length of $1024$. The forward-pass time increases by $2.70\%$, slightly exceeding the relative increase in parameter count, while the final training loss decreases from $3.2$ to $3.1$ ($-3.125\%$). According to scaling laws~\cite{kaplan2020scaling,hoffmann2022training}, such a substantial loss reduction would require increasing the model size to approximately $200$M parameters ($+60\%$). In addition, although the wall-clock training time increases by about $5\%$, the number of training tokens required to reach the final loss of RoPE baseline decreases from $3$B to about $2.34$B ($-22\%$).

\subsection{2D Position Embedding}

To produce 2D positional embeddings, we use 2D convolutional layers that take
a 2D window input and produce a 2D window output. We use ViT-Tiny~\cite{dosovitskiy2021image} models with Multi-Head Attention (MHA) and the configuration
$N_{\mathrm{layers}}=12$, $D_{\mathrm{model}}=192$, $N_{\mathrm{heads}}=3$, and $D_{\mathrm{head}}=64$. We train the models on CIFAR-10 and CIFAR-100~\cite{krizhevsky2009learning} for 100 epochs with patch shape $4\times4$.

Table~\ref{tab:cifar} shows that ConvPE transfers effectively to vision transformers and outperforms the RoPE baseline. The influence of hyperparameters requires further study on larger models and datasets.

\section{Conclusions and Future Work}

ConvPE delivers substantial performance gains at a minor parameter and computational cost, providing a powerful alternative for positional embeddings. We adopt $H_b=1$ without any parameter-saving technique as the default configuration, which achieves the best balance among performance, parameter efficiency, and computational cost. ConvPE is compatible with RoPE, various attention masks, and KV-cache concatenation, and it naturally supports multidimensional extensions. 

Future work can explore the following directions:
\begin{itemize}
    \item \textbf{Kernel Optimization.} Further optimize the backward kernel and develop additional kernels for a wider range of hardware.
    \item \textbf{Scaling behavior.} Investigate ConvPE with larger Transformers and datasets, and identify configuration patterns at scale.
    \item \textbf{Long-context modeling.} Evaluate ConvPE in long-context settings, where positional generalization is particularly important.
    \item \textbf{Architectural integration.} Combine ConvPE with Sliding Window Attention (SWA)~\cite{beltagy2020longformer}, Compressed Sparse
    Attention (CSA)~\cite{deepseek2026v4}, and other Transformer variants.
    \item \textbf{Multidimensional modalities.} Extend ConvPE to high-dimensional modalities such as vision, speech, and multimodal data.
\end{itemize}
